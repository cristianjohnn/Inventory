## Reading Order for New Developers

If you just joined the team, read the docs in this order:

```
1. README.md              ← Set up the project
2. GLOSSARY.md             ← Learn the terminology
3. ARCHITECTURE.md         ← Understand the project structure
4. FRONTEND_BACKEND_MAP.md ← See how the pieces connect
5. WORK_SPLIT.md           ← Find out which files you own
6. BRANCH_STRATEGY.md      ← Learn the Git workflow
7. CONTRIBUTING.md         ← Know how to submit code
```

**Total reading time:** ~30 minutes. After that, you're ready to code.

## Doc Descriptions

| Document | What's Inside | When to Re-read |
|----------|---------------|-----------------|
| **ARCHITECTURE.md** | Tech stack, folder structure explained, why there are so many root files | When you're confused about where something lives |

| **BRANCH_STRATEGY.md** | Branch flow, naming conventions, daily workflow, merge strategy, common mistakes | When you're about to create a branch or open a PR |
| **COLLABORATORS.md** | GitHub permissions, branch protection setup, onboarding checklists | When adding a new team member |
| **GLOSSARY.md** | Definitions for Git, React, Express, and project-specific terms | When you encounter a term you don't understand |
